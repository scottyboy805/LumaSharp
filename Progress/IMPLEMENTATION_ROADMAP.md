# LumaSharp implementation roadmap

This roadmap tracks implementation against `LumaSharp_LanguageSpecification.md` and `LumaSharp_CompilerSpecification.md`. A feature is complete only when parsing, semantic checks, code generation/runtime behaviour, diagnostics, and focused conformance tests agree with the specification. Unsupported syntax must produce a stable diagnostic rather than silently compiling with placeholder behaviour.

## Current baseline

Parameter lifetime syntax now uses `scope`; `readonly` is not accepted on parameters, and `in` is the read-only reference form. `scope` composes with `ref`, `in`, and `out`; semantic analysis tracks escape lifetime separately from mutability so scoped `ref`/`out` remain writable. Ordinary heap values are also valid arguments to `scope` parameters and receive the same non-escape checks in the callee. Focused tests cover valid scoped `in`/`ref`/`out`, passing a scope allocation to `in`, rejected escape through `in`, and rejection of the old `readonly` parameter syntax.

Virtual overrides must explicitly match every base parameter's passing mode and `scope` modifier. Override validation reports LS0832 for either a missing or additional `scope`; Stream runtime overrides and helper methods now preserve the borrow contract.

Computed property setters no longer receive a synthetic return statement when every path already returns or throws. This removes a false LS3001 warning attached to the following property declaration while preserving implicit setter completion when the body can fall through.

The compiler-known runtime surface is now represented in `LumaSharp.Library`: `System.Object`, `System.Array`, `System.Delegate`, the exception hierarchy, and the `System.Collections.IEnumerable<T>`/`IIterator<T>` protocols. The `for-in` lowering recognizes these moved namespace contracts and continues to accept legacy global declarations. Array shape/length access and string storage/operators remain compiler intrinsics. Compiler-generated fallback declarations remain available for standalone compilation, while declarations in the selected runtime sources replace those fallbacks and can gain ordinary source members. The compiler packages the runtime sources beside its installation and discovers them automatically; source-tree ancestors are also searched, and projects can select a runtime directory with `runtimeLibraryPath` or `--runtime-library`. Runtime source files are compiled with runtime-only unsafe permission so application unsafe settings remain unchanged.

The first generic collection runtime is in `System.Collections`: dynamically growing array-backed `List<T>`, `Stack<T>`, and `Queue<T>`, plus open-addressed `Dictionary<TKey, TValue>` and `HashSet<T>`. List, stack, queue, and hash set implement the `IEnumerable<T>`/`IIterator<T>` protocol through nested iterator types; dictionary enumeration remains open. The compiler resolves nested generic iterator types through closed generic parents so these runtime implementations can construct their iterator specializations. List iterates in insertion order, stack from top to bottom, queue from head to tail, and hash-set order is unspecified. Hash-based collections constrain keys to non-null reference types implementing `IEquality<T>` and `IHashable`; primitive-key comparers and broader equality/comparer APIs remain open. A native smoke executable successfully iterates list, stack, and queue; focused compiler execution coverage also covers namespace resolution, growth/rehashing, lookup, and duplicate handling.

The list benchmark measures both implementations internally: C# uses `Stopwatch`, while LumaSharp uses `StopWatch`, excluding compilation and process startup. The original workload included `ToArray()` once per iteration; a Windows Release run at 250,000 iterations over seven samples produced matching checksum `9`, median C# time 12.406 ms (12.037–13.797 ms), and median LumaSharp time 17.186 ms (16.584–17.793 ms). After removing `ToArray()` from both sides to focus on core list APIs, seven samples produced matching checksum `8`, median C# time 12.430 ms and median LumaSharp time 8.754 ms (8.613–9.185 ms); LumaSharp was about 1.42 times faster in this run. The `ToArray()`-inclusive timing therefore appears to account for the earlier reversal, though the two paths have not been profiled independently. `dotnet test` stalls after test discovery in this environment, so these measurements were captured with a temporary direct runner using the same sources and internal timers.

The compiler currently emits a pending-exception load and branch after each non-extern call when exception handling is enabled, because the switch is module-wide. A conservative transitive may-throw analysis could remove checks from proven non-throwing calls while retaining checks where exceptions can be raised. This remains a possible optimization, but the core-list benchmark without `ToArray()` is already faster than C#; further optimization should be guided by profiling rather than assuming call checks are the current bottleneck.

Primitive keyword aliases now resolve their standard-library types (`System.Int32`, `System.Bool`, `System.String`, and peers) for member access. Each numeric/boolean/character primitive has its own source file; value primitives are structs with the special `System.ValueType` struct marker as their base, while `string` remains a reference type. Boxing is an implicit compiler operation that gives boxed primitive, enum, and struct values an `object` descriptor base. Primitive `ToString()` emits the actual value for all integer widths, native integers, booleans, characters, floats, and doubles; booleans use `True`/`False`, floating special values use `NaN`/`Infinity`/`-Infinity`, and boxed primitives preserve their value formatting. Non-primitive types retain the default type-name formatting. Runtime declarations expose integer bounds, floating bounds/special values, bool/char/integer/floating `Parse` and `TryParse`, numeric `ToString()`, and common `String` helpers. Parsing currently uses invariant ASCII decimal syntax; culture/provider and number-style overloads remain unsupported.

Switch sections, guarded labels, catch bodies, and successful `is T name` condition branches now have lexical capture scopes. Locals declared directly in a section share mutable storage with closures that escape the section; pattern variables and caught exception variables are retained in managed closure environments before guard/body execution. Lambdas in the successful right operand of `&&` receive a separate retained copy so condition evaluation does not consume the binding needed by the body. Guard environments are released on both match and non-match paths, and catch and condition environments on their exits, while escaping delegates retain them. Runtime coverage exercises guard-, catch-, body-, and condition-created closures stored beyond their scopes.

The compiler has a C# library and CLI, a custom lexer/parser, semantic analysis, LLVM IR generation and verification, native object emission/linking, project-file validation, and xUnit integration tests. The supported language subset is summarized in the repository README. Exception statements now lower to a two-phase handler search, cross-method propagation, ordered typed/catch-all dispatch, rethrow, scope cleanup, `finally` on normal/exception/return/break/continue exits, and replacement when a `finally` throws. Checked arithmetic, null assertions, string/array bounds, invalid array dimensions, class/array allocation, explicit class-cast failures, constructor failures, and dynamic string-helper allocation failures raise catchable exceptions. String allocation tests inject failures at every allocation stage and verify partial allocations are released. Class constructor completion is tracked so failure cleanup runs only the finalizers of classes whose constructors returned successfully. Unhandled exceptions report their dynamic type, message, and inner-exception chain; handler globals use LLVM thread-local storage. The in-process MCJIT harness rewrites TLS globals to ordinary globals for single-threaded execution because MCJIT does not implement the host TLS relocation model; emitted object code retains thread-local storage.

The compiler-known `System.Array` base is modeled as a runtime class derived from `System.Object`. Managed array descriptors derive from `System.Array`; array references convert to `Array`/`object`, and `Array`/`object` type patterns in switches recognize the common array bases, including nullable null coverage and subsumption; `Array`-typed values support dynamic `Length`, `Rank`, and bounds-checked `GetLength`. Nullable base access, runtime `is`/`as`/checked casts, reference-identity comparisons across array/base references, inherited `ToString` dispatch with dynamic array names, base-typed parameters and returns, and the specified out-of-range exception have focused execution and diagnostic tests. The intrinsic base cannot be constructed or subclassed by source code, and built-in fallback resolution preserves existing namespace/name lookup precedence.

Unsafe pointer lowering distinguishes value storage from class objects: pointers to structs designate their storage, while class pointers are non-owning references to the object. Class-pointer field/property/indexer/method access operates on that object; explicit dereference retains a normal managed reference, and address-of mutable static fields now resolves to the field's storage. Focused execution tests cover local and class-field addresses, virtual dispatch, indexing, dereference ownership, static-field address mutation, and readonly/invalid targets.

Generic method inference collects reference and numeric lower bounds across direct arguments, lambda outputs, and method-group returns before fixing a type, so later bounds can resolve an initially ambiguous interface or numeric set. Numeric candidates must accept every lower bound under LumaSharp's implicit conversion rules; an incompatible set reports LS1101. Exact bounds from by-reference arguments, explicit lambda parameters, and invariant containers remain distinct. Nullable reference/value bounds are also combined. Constructor constraints reject abstract class arguments while accepting fully implemented derived classes. Generic-body checks diagnose unconstrained `T` locals, `default(T)`, and struct fields; unconstrained `T[]` allocation is accepted when the requested length is zero, while specialization applies ordinary array element-initialization rules to non-empty arrays. Conditional expressions use the same common-reference selection for interface-typed branches, including nullable branches. Interface references also convert to the compiler-known `System.Object` root. Statically typed lambda returns contribute bounds beyond literals and casts. Expression-bodied and block-bodied lambdas can infer from arithmetic, conditional expressions, captured locals, and calls with known result types. A target-dependent output such as `default` no longer suppresses bounds from other known return paths. The probe analyzes cloned expressions in an isolated method context and discards speculative diagnostics; unresolved target-dependent expressions defer to other arguments or explicit type arguments.

Generic method-group arguments now contribute bounds from compatible delegate signatures. Parameter signatures provide exact type information, return types provide result bounds, and overload candidates are filtered using type arguments inferred from the other call arguments before the selected delegate conversion is bound. Static and instance groups are covered, including instance receivers discovered by analyzing an expression in an isolated context. Generic static and instance methods specialize from the closed delegate signature, with constraints checked before the delegate binding is accepted.

Delegates are lowered as reference-counted function/target objects. Static and instance method groups support retained receivers, virtual dispatch, identity equality, invocation, class fields, arrays, nullability, and closed generic specialization, including delegates first closed through a specialized generic method signature. Target-typed lambdas use generic type arguments inferred from other call arguments, explicit lambda parameter types, or statically typed lambda return expressions, then capture method-scope locals, by-value parameters, C-style `for`-header variables, `for-in` iteration variables, and class or struct `this`. Method captures share a managed environment; each entered C-style `for` scope allocates an environment shared by closures across iterations. Captured class receivers are retained; struct receivers are copied into the closure environment, and mutation is allowed only when the enclosing struct method is `mut`. Non-mutating receiver writes report `LS0821`, and calls on scope-bound receivers report `LS0702`. Ref/in/out captures (`LS0730`) and scope-bound/readonly escapes (`LS0701`) receive explicit diagnostics; scope-bound lambdas can borrow scope-bound references within their lexical lifetime and as direct arguments to readonly delegate parameters. Composite environments retain captures from multiple lexical scopes, including the enclosing receiver; nested lambdas retain outer closure state and mutable parameters. Nested blocks and `for-in` iterations capture their own locals through per-entry managed environments. Struct method-group boxing creates an owned value copy and recursively retains its managed fields. Generic classes, structs, and interfaces specialize closed constructions before binding, substituting type arguments through fields, constructor/method signatures and bodies; nested generic arguments, per-instantiation static storage, class/interface dispatch, and constructed generic type aliases have executable coverage. Basic `class`, `struct`, `enum`, base/interface, `new()`, and `new(parameter types)` constraints are checked at each construction with `LS1102`; the `class` constraint accepts non-nullable delegate types and rejects nullable delegate types. Generic methods support explicit type arguments, per-call specialization, method constraints, inference for direct, nullable, array, nested-generic, numeric, common-base reference, constructed-interface, and constructed generic-base patterns, the non-generic overload tie-break, and structural specificity comparison between specialized generic signatures; incomparable candidates remain ambiguous with LS0750. Constraint-body checking verifies direct member names/accessibility, overloaded method signatures and known argument conversions, and constraint overload matching checks delegate lambda and unqualified method-group parameter/return signatures, preserves statically known arithmetic, conditional expressions, and explicit or inferable unqualified/static direct/array/constructed-generic helper-call results with common numeric lower-bound inference, uses the selected target pointer width for native integer promotion and conversion, and rejects mismatched overloads even in uninstantiated generic bodies, generic interface substitutions, property and indexer accessors/setter types, and operators supplied by class constraints; class-constrained equality uses reference identity. Receiver paths through constrained fields, properties, method returns, and indexer results are checked after substitution. Calls with types the checker cannot infer and more complex overload inference remain incomplete. Generic virtual/interface methods are excluded by the v1 specification and receive an explicit LMC3000 diagnostic. Expansive recursive generic instantiations fail with an explicit diagnostic instead of recursing indefinitely. Non-generic and specialized interface declarations, inherited contracts, public implicit class/struct implementations, and explicit class method/property/indexer implementations are validated with `LS1001` for missing members. Class-backed interface references support conversions, method and accessor dispatch, runtime implementation tests/casts, and managed ownership. Class- and struct-backed `IEnumerable<T>` iteration lowers through `Iterate()`, `Next()`, and `Current`; normal completion, `break`, `continue`, interface-typed sources, malformed protocols, and iterator cleanup have focused coverage. Struct-backed enumeration lowers through owned interface boxing and the normal iterator protocol; ambiguous element types report `LS0640`. Complete generic constrained operations and constraint-only expression checking remain incomplete.

Closed generic interfaces now pass through specialization and interface contract validation, with execution coverage for specialized method signatures, class dispatch, inherited contracts, and struct boxing through a closed interface reference. Generic methods declared inside interfaces remain unsupported and receive a focused compiler diagnostic.

Inline `out` locals now carry their lexical closure owner through analysis and lowering. Captures declared in nested blocks use the block's managed closure environment, so the callee's assignment and later closure mutations address the same storage after the block exits.

The aggregate slice supports sequential structs with primitive, enum, pointer, nested-struct, and inline-array fields; target-specific layout and `sizeof`; default values; value copies through assignment, parameters and returns; parameterized constructors; ordinary and `mut` instance methods; unqualified and `this`-qualified field access; mutable-receiver diagnostics; inline-array fields/elements with indexing and `for-in`, including instance and static inline-array class fields, struct field initializers, collection initializers, and arithmetic/`const`/enum/`sizeof` constant lengths; auto-properties; and user-defined unary/binary operators with derived compound assignments and `!=` lowered as the negation of `==`. Class and struct overloads share conversion-ranked binding and call lowering; class operands retain and release references through the normal call-ownership path. Nullable scalar/enum/struct values use an all-zero-null tagged aggregate, support lifted scalar operators and equality, and allow flow-proven or asserted in-place struct member/mutating-method access. LLVM verification and object emission cover host end-to-end aggregate and equality cases; 32-bit and 64-bit compiler layout tests cover C alignment and padding. Nullable reference fields inside structs are supported with recursive retain/release through nested structs and inline arrays; cross-target object execution remains open. Computed and explicit properties now lower to accessor methods, and computed class/struct indexers support overloads and class virtual dispatch.

The string slice decodes ordinary and verbatim literals into immutable UTF-8 objects with NUL-terminated storage, UTF-16 code-unit caches, a type/header prefix, and immortal flags. Its unsafe `Ptr` property exposes the current UTF-8 data pointer for native interop. It supports shared empty defaults, `Length`, read-only indexing with caller-side bounds checks, content equality, string constant switch labels, string constant fields with compile-time literal concatenation, numeric/string const-to-const folding with forward dependency resolution and cycle diagnostics, and unqualified in-class const references, and dynamic concatenation of strings, null, booleans, characters, integers, floating-point values, enums, and classes/structs using `ToString`. Enum and default struct values return fully qualified type names; class references dispatch through a virtual `object.ToString` slot and use the dynamic type name by default. Class overrides dispatch through base and interface references, including direct calls and concatenation; null-conditional class/interface `?.ToString()` is supported. Dynamic override results enter normal owned-string cleanup, including when the override builds a new string. Nullable strings support null-preserving local/class-field storage, null-aware equality, flow assertions/refinement, coalescing and concatenation, and null-conditional `Length`, fields, and calls. Owned strings use reference-counted runtime allocation/release; JIT tests cover nullable values, concatenation, UTF-16 indexing, primitive formatting, simultaneous assignment, balanced scope/temporary cleanup, and catchable out-of-memory errors for all string allocation stages with partial-allocation cleanup. Invalid string indices now raise `IndexOutOfRangeException` through generated caller code. `System.String` now has source-level constructors from character arrays and repeated characters, plus substring/search/prefix/suffix/replacement/trim/character-array helpers; construction lowers to owned runtime strings, while executable literals remain immortal and non-owned. Public non-mutating struct `ToString()` overrides are called directly and during string concatenation; nullable string fields inside structs use recursive aggregate ownership. Static references intentionally live until process exit per the runtime specification.

Strings use runtime descriptors derived from `System.Object`, with dynamic retain/release callbacks and a `ToString` vtable entry. Strings and managed arrays can be assigned to `object` and used as operands for exact runtime type tests, pattern bindings, `as`, and primitive unboxing checks. Array descriptors derive from the compiler-known `System.Array`, which derives from `System.Object`. Checked casts from object references to `string` raise the specified null or invalid-cast exceptions; JIT coverage also verifies failed tests and casts release owned values.

The managed-array slice supports rank-one arrays, rectangular rank-two/rank-three arrays, and recursive jagged arrays with numeric, boolean, character, enum, string, class-reference, delegate, nullable-string, nullable-class, nullable-array, nullable-value, and struct elements containing nullable managed references. Arrays remain invariant, and attempted class-array covariance reports `LS1502`. It lowers allocation and nested collection initializers, uses contiguous row-major storage for rectangular arrays and independently managed child arrays for jagged arrays, checks bounds per dimension, implements `Length`, `Rank`, `GetLength`, and row-major `for-in`, and retains/releases aliases, parameters, returns, `ref`/`out` element writes, nested replacements, and reference elements recursively. Non-nullable class and nested-array elements require complete initializers; nullable forms start as null while `string` starts as the shared empty string. Nullable array variables, fields, parameters, and returns use nullable pointer storage with ownership-aware `??`, `??=`, flow-checked indexing, `?[]`, and null-conditional `Length`/`Rank`; tests cover null and present results, aliases, class fields/methods, and balanced cleanup. Scoped arrays use lexical cleanup; lifetime-compatible scoped class and nested-array elements retain their references through container destruction. Scope-bound delegates that capture scoped references may also be stored in scoped delegate arrays, where invocation remains valid through the array lifetime; heap-array storage and returning such an element receive LS0701. Scoped class owners can also store scoped class, managed-array, or scope-bound delegate references through proven-safe direct field assignments and simple constructor stores, with declaration order and shorter nested lifetimes enforced; direct fields, computed properties, indexers, and class/array-returning calls preserve field escape checks. Null-initialized locals may receive scoped or `readonly` borrowed aliases when their lifetime is the same or shorter, including `in` parameters and class, array, string, and delegate values; alias locals retain balanced runtime references through lexical cleanup and closure environments. Multiple assignment snapshots managed references before stores, pins array/class receivers, evaluates values before targets, and supports local aliases, fields, managed-array and pointer elements, computed property/indexer setters, pointer dereferences, and class-pointer fields; tests cover throwing target evaluation and accessor sequencing. Inner-to-outer escapes and heap rebinding receive `LS0701`, and tests verify destruction order and allocation balance. Broader readonly and closure-container escape checks remain open. Runtime helper allocation returns structured status so generated callers raise catchable overflow and out-of-memory exceptions; caller-side checks also raise for invalid dimensions, bounds, and `GetLength`. Struct elements containing nullable managed references use per-array element strides and aggregate release callbacks. A shared versioned runtime ABI and standalone runtime package remain incomplete.


The class-object slice supports explicit and implicit constructors, target-typed `new()` with required `LS0802` when no expected type exists, constructor overload binding with named/optional arguments, explicit `: this(...)`/`: base(...)` initializers, field, method, constructor, and public API type accessibility checks (`LS0840`), derived field-initializer-before-base execution, transitive field assignment through `this` chains, constructor `this` restrictions and `LMC3014` delegation-cycle diagnostics. A hidden completion flag prevents a delegated constructor from marking its class complete before the outer body returns. It also supports the built-in `System.Object` root and the `object` alias, with default and custom virtual `ToString()` dispatch, inherited fields, readonly instance fields, base conversions and direct `base` field/method access, single class inheritance, abstract virtual methods, virtual dispatch through class descriptors/vtables, static classes (static-only members, non-instantiability, and no inheritance), unqualified implicit-`this` calls to class and struct methods, and primitive/enum/struct/string/class-reference/managed-array/inline-array fields and field initializers, including nullable managed references recursively owned inside structs. Class-reference and interface-reference type tests, conditional casts, and checked casts use dynamic descriptors; class-backed interface conversions and method/property/indexer dispatch use per-class interface tables. Primitive, enum, and struct boxes support exact type tests, conditional casts, checked unboxing, recursive reference ownership, and struct-backed interface dispatch. Complete generic constrained expression checking remains incomplete; struct-backed enumerable lowering uses the owned box and interface-dispatch path. Class `mut` checks, identity equality, object headers, per-class reference counting, reverse-order reference-field cleanup, deterministic `~this()` finalizers, required `LS3301` static strong-reference-cycle warnings, and constructor-failure finalization rules are implemented. Finalizers enter the destroying state before running, and `this` escape to non-readonly parameters is rejected. Scope-allocated class and supported array locals use block cleanup; scope aliases retain balanced references until lexical cleanup, temporaries are destroyed at statement end, and return/store/parameter/receiver escape diagnostics are implemented conservatively. Nullable class, string, and array references support null initialization/comparison, flow through local and member paths, short-circuit conditions, conditional expressions and loop bodies, assertions, coalescing and coalescing assignment, nullable fields, and ownership-aware null-conditional field, method, length and index access; nullable value-returning access yields `T?`. Class aliases, call arguments, returns, and scope exits are tracked. Nullable value types include scalar, enum, and struct equality/lifted-operation and member-access support. Constant and null `switch` patterns now support nullable governing values, `not null`, discard cases, ordered boolean `when` guards, duplicate/subsumption diagnostics, and guard evaluation only after a pattern matches; guarded duplicates remain reachable until an earlier unguarded case subsumes them. Loop-flow analysis records `continue` paths, excludes dead statements after abrupt transfers, joins constant-true loop exits from actual `break` paths, and treats unbreakable constant-true loops as non-fallthrough in return and `out`-parameter checks. Nullable-flow analysis rechecks while, do, for, and for-in loop bodies until the iteration state converges; more precise early-exit reachability remains open. Full scope/readonly container analysis remains open. The object-model exit gate still requires a shared runtime ABI/package and release-grade tests.

The method-call slice now supports `T... values`: trailing values are gathered into an owned managed array, zero arguments produce an empty array, and a single array argument uses no-copy normal form so mutations alias the caller's array. Optional fixed parameters may precede the final variadic parameter. Conformance tests cover numeric expansion, aliasing, optional defaults, managed string elements, and invalid declarations. Native C ABI variadic declarations receive a diagnostic because the managed array convention does not match C varargs.

Auto-properties with semicolon-only `get` and optional `set` accessors lower to synthesized accessors backed by checked storage for classes and structs; accessor-specific accessibility and mixed auto/explicit accessors are supported. Primitive and reference-bearing struct field and property initializers run before parameterized struct constructor bodies, while default struct construction remains zero initialized. Properties that use compiler-provided `field` backing storage can have initializers; computed properties without backing storage cannot. Computed and explicit-body properties lower to methods with contextual `field` backing storage and class virtual/override dispatch. Computed class and struct indexers support expression and block accessors, multiple and overloaded parameters, setter mutation checks, null-conditional reads, and class virtual/override dispatch. Compound and coalescing assignment through computed properties and indexers preserve single evaluation and only call setters when required. Class-backed interface property and indexer accessors also validate and dispatch, including after generic specialization. Compile-time static readonly primitive and string storage and get-only static primitive auto-properties still emit LLVM constants where possible. Managed-reference field/property initializers in structs use recursive aggregate ownership; auto-indexers remain unsupported.

Static initialization is lazy and once-only per concrete type, with declaration-order field initializers followed by `static this()`, base-before-derived ordering, and triggers on static field/method/property access and class/struct construction. Atomic state transitions and thread-local in-progress tracking provide concurrent waiting and same-thread circular-access detection. Failures are wrapped in `System.TypeInitializationException`, retain the original inner exception, and rethrow the cached wrapper on later access; entry-type failures stop before `Main`. Primitive, enum, struct, pointer, string, class-reference, delegate, and managed-array statics are supported, including program-lifetime ownership for reference statics. Static interface fields are diagnosed as unsupported. Readonly and non-nullable static fields without declaration initializers are checked across static-constructor normal exits through structured if/switch statements and loops. The flow tracks guaranteed `do` execution, constant loop conditions, iterator assignments, loop labels, `break`/`continue`, and assignments in `finally`; unknown loop conditions retain the zero-iteration path, and complex exception/abrupt-control combinations remain conservative.

Switch patterns support constants, null, discard, nullable numeric relational operators (`<`, `<=`, `>`, `>=`), and combined `and`, `or`, and `not` patterns. Numeric subsumption analysis intersects combined `and` ranges and detects coverage by the union of earlier unguarded ranges while preserving gaps at exclusive endpoints. String, class, interface, delegate, and array type patterns use direct checks, runtime descriptors, or interface tables, work with nullable reference governing values, and check direct subsumption. Primitive and enum type patterns use exact value identity for value governing types and exact runtime box descriptors for object governing values; declaration variables bind decoded values and are visible to guards and section bodies. Variables may be introduced by multiple `and` patterns, and are accepted across `or` alternatives or comma-separated labels only when every alternative binds the same names and types; invalid or-pattern bindings receive a type diagnostic. Runtime array descriptors are attached at allocation and allow exact array `is`/`as`, array type-switch patterns, and array-to-`object` checks while preserving dynamic release. Return-flow analysis recognizes exhaustive boolean, enum, integral numeric, and reference switches where the governing reference type itself is covered, including exact non-null primitive/enum/struct patterns (and nullable struct patterns with explicit null coverage), nullable domains, integer-adjacent relational ranges, nullable `not null` coverage, and duplicate enum aliases.

`is T name` patterns now bind in true `if`, `while`, and C-style `for` bodies and on the right side of `&&`. The lowerer preserves reference lifetimes across repeated and short-circuited tests, exposes the bound value to the successful branch, and emits runtime descriptors for types referenced only by a type test. Strings derive from `System.Object`, while managed arrays derive from `System.Array`; exact runtime checks, object conversion, checked string/array casts, primitive unboxing checks, and declaration bindings are covered for direct reference and object-reference operands, with JIT checks for failed casts and balanced ownership. Semantic analysis reports `LS3101` for constant string, array, primitive, and class type tests.

## Nested type slice

Nested class, struct, interface, and enum declarations are lowered under qualified names such as `Outer.Inner`. The parser records containing types explicitly, so private type/member access follows lexical containment rather than namespace-string coincidences; nested types default to private visibility, nested class members can access private members of the containing class, and private nested types referenced outside their accessibility scope produce `LMC3012`. Accessibility checks generic and array type constituents plus containing types in declarations, `is`/`as`, explicit casts, `default`, `sizeof`, allocation, static field/method access and method groups, switch patterns, catch types, base/interface lists, generic constraints, explicit generic method arguments, and file-level aliases (including aliases in otherwise empty files), avoiding unresolved-name cascades where these paths have dedicated binders. File-scoped namespace placement and uniqueness are validated; unsupported block-scoped namespaces receive `LMC3000` rather than silently compiling.

## Ordered work

### 1. Front end and semantic completeness

- Continue replacing string-encoded type names with a structured type model that preserves generic arguments, array ranks, nullability, pointers, and inline-array lengths. A structured type-name parser now drives generic-use discovery, exact type-parameter detection, generic substitution/splitting, managed/inline array decomposition, type-constituent enumeration, pointer checks, and nullable-type classification; its suffix nodes distinguish array rank, inline-array length, nullability, and pointers. Parser-to-typed-AST migration and conversion of the remaining semantic-analyzer string checks remain open.
- Complete grammar coverage and recovery for every syntax form in Part I, and declarations currently represented by `UnsupportedMember` or `UnsupportedExpression`.
- Add declaration binding, accessibility, overload resolution, generic constraints, complete nullable flow, definite assignment, `mut` receiver checks, and ownership/escape analysis.
- Keep a diagnostic conformance test for every required error and warning code in the specifications.

**Exit gate:** every specified syntax form parses into a typed representation; valid programs reach lowering, and invalid programs fail with source-located diagnostics without crashing or emitting placeholder code.

### 2. Value types and aggregate layout

- Complete C ABI layout rules and padding for every supported target width, and test both 32-bit and 64-bit targets.
- Implement nullable reference fields in structs with copy/overwrite ownership, retain/release, and destruction ordering.
- Complete cross-target aggregate layout and execution coverage; nullable reference ownership in structs, nested inline arrays, managed arrays, and boxes now uses recursive retain/release.

**Exit gate:** layout and copy tests pass for nested structs, constructors, methods, and inline arrays on 32-bit and 64-bit targets; nullable reference ownership is exercised at runtime; LLVM verification passes for each case.

### 3. Object model and runtime foundation

- Define runtime ABI and ship the statically linked runtime specified in Part II.
- Complete classes and object allocation with remaining accessibility/flow rules, class member semantics, runtime type behavior, and complete constructor/destructor failure paths; package type descriptors, retain/release, deterministic destruction, and startup/shutdown in the shared runtime ABI.
- Implement exceptions and specified runtime failures (including overflow, bounds, null, cast, allocation, and type-initialization failures) rather than backend traps.
- Complete strings and arrays with the specified object descriptors, full element ownership, jagged and scoped arrays, and exception-compatible bounds/allocation failures.
- Implement `scope` allocation and lifetime/escape enforcement.
- The initial `System.IO` filesystem layer is emitted directly as target-specific LLVM calls, with no packaged C shim. The `System.IO.NativeFileSystem` compiler ABI currently provides file open/read/write/seek/resize/flush/close, file and directory existence, directory create/delete, file copy/move, current/temp directory retrieval, and standard-output writes. Its open-mode identifiers are named public constants (`OpenMode`, `CreateMode`, `AppendMode`, `OpenOrCreateMode`, and `CreateNewMode`). LumaSharp wrappers provide `FileStream`, basic `File`/`Directory` operations, lexical `Path` helpers, `TextReader`/`TextWriter` base APIs, and `Console.Write`/`WriteLine` overloads for strings and characters. `TextWriter` also provides primitive formatting helpers. Windows writes UTF-8 bytes through the standard output handle; POSIX targets use libc `write`. `FileStream` stores native handles in platform-sized `int`, with emission checks for 32- and 64-bit Windows and POSIX targets. File/directory enumeration, recursive directory deletion, and canonical `.`/`..` path normalization are not implemented yet.
- `System.Environment` reports the executable path, directory, and name; processor count; endianness; and target `Platform` and `Architecture` enums. The compiler emits Windows, Linux, and macOS shims directly in LLVM, with target-derived enum values and native processor/path queries. Windows x86/x64, Linux x86/x64, and macOS ARM64 IR verification plus a Windows native smoke program pass. Pointer-width path lengths are emitted without invalid same-width LLVM truncations.
- `System.Diagnostics.StopWatch` measures monotonic elapsed time using Windows `QueryPerformanceCounter` or POSIX `clock_gettime(CLOCK_MONOTONIC)` shims emitted directly in LLVM. The counter frequency is read once per stopwatch; `Elapsed` converts accumulated counter deltas to `System.TimeSpan` ticks (100 nanoseconds). `TimeSpan` exposes `Ticks`, `TotalMilliseconds`, and `TotalSeconds`. Runtime tests cover state transitions and compare a 400 ms native sleep against a 350–600 ms tolerance; target-specific LLVM emission is checked for Windows x86/x64, Linux x86/x64, and macOS ARM64.

**Exit gate:** generated programs link and run against the bundled runtime; lifetime, exceptions, arrays, strings, and initialization tests validate observable behavior, not only LLVM shape.

Readonly captures are borrowed by scope-bound closures and rejected when they escape; composite multi-scope captures, base-qualified field/property/method access, and nested lambda parameter captures have execution coverage.

## Active focus

`System.Enum` is a value-type runtime helper with generic `GetValues<T>(T value) where T : enum`. The compiler specializes each closed call from enum declarations, including aliases, and emits a normally allocated typed array sorted by unsigned underlying value (declaration order breaks ties). A native fixture validates signed values, aliases, generic inference, and returned values. A focused xUnit regression was added, but `dotnet test` still exits without diagnostics in this environment.

Generic `default` constraints now express that a type argument has a default value, accepting value types and nullable references while rejecting non-nullable references. The compiler allows `default(T)` and initialized `new T[length]` only with that constraint (or `struct`/`enum`), while nullable element arrays remain available to unconstrained code. `List<T>`, `Stack<T>`, `Queue<T>`, `HashSet<T>`, and `Dictionary<TKey,TValue>` use constrained non-nullable backing arrays initialized to `default(T)`, and contiguous collection `Ptr` members now describe the element type directly. CLI and runtime builds plus a native `default`/array/List pointer smoke program pass. The compiler xUnit project still cannot build in this environment because the .NET SDK workload resolver fails without diagnostics.

An opt-in xUnit project at `Tests/LumaSharp.Benchmarks` builds a standalone editable LumaSharp `List<T>` workload to a native executable and compares it with the equivalent C# `List<int>` operation sequence. The LumaSharp fixture, C# workload, and test runner are split into separate source files. The test checks a checksum before reporting median timings and labels native process startup in the measurement. The `List<T>.Ptr` nullable-element pointer mismatch was fixed with an explicit unsafe pointer conversion. `List<T>`'s `IEnumerable<T>` interface and nested iterator are temporarily disabled because the backend cannot allocate the specialized iterator. The test runner still times out connecting to testhost, but direct native execution succeeds. Collection array operations whose indices are already range-checked or established by a bounded loop now use `unsafe unchecked`; public index validation remains in place. After this optimization, a direct run of the same 100,000-iteration workload with five samples produced checksum 100, C# median 10.472 ms, and LumaSharp median 24.841 ms including native process startup. These exploratory timings are not directly apples-to-apples because only the LumaSharp timing includes process startup.

The first collection-runtime slice is in place under `System.Collections`: `List<T>`, `Stack<T>`, `Queue<T>`, `Dictionary<TKey,TValue>`, and `HashSet<T>` use lowercase fields, nested iterator types, and unsafe `Ptr` views; dictionary keys are unconstrained and may use `System.IEquality<T>`/`System.IHashable` when available. The two contracts now live in the root `System` namespace, with `IHashable.Hash` as a getter, and the collection-only guard helper has been removed. Pointer-backed `System.Span<T>` and `System.ReadOnlySpan<T>` provide bounds-checked indexing (the pointer access is inside `unchecked` after the explicit range check), bounds-validated slicing, read-only conversion, and static `Empty` properties that return their default zero state. User-defined conversion operators are now parsed, validated, considered during implicit conversion and cast analysis, and lowered as direct calls. Exact source/target matching is supported; conversion chaining is not. Generic struct constructor calls now resolve type arguments to their closed specialization before constructor selection. `List<T>` converts implicitly to `Span<T>` and `ReadOnlySpan<T>`, and `Span<T>` converts implicitly to `ReadOnlySpan<T>`. A native runtime fixture verifies all three conversions. A standalone `.ls` smoke program exercises implicit assignment and an explicit cast end-to-end in a built native executable (exit code 0), and an explicit-only conversion is rejected for implicit assignment. Single-dimensional arrays also convert implicitly to both span types through internal generic helpers in `System.Array` (`Array.ls`), which the compiler binds as conversions. Managed arrays expose an unsafe typed `T* Ptr` intrinsic to their first element; it returns null for empty arrays, and conversions produce zero-state spans for empty inputs. The runtime fixture for array pointers, explicit Empty values, and array-to-span conversion builds and runs natively with exit code 0. The generic array conversion helpers use `Span<T>.Empty` and `ReadOnlySpan<T>.Empty` for empty inputs; the compiler lowers these open-generic Empty accesses to the zero value of the corresponding closed span type. The array helper methods already act as implicit conversions through compiler binding. They are not declared as conversion operators because `System.Array` is not the `T[]` source type or either span target, and conversion operators currently cannot declare their own generic type parameters. Ref-struct-like restrictions that prevent spans from being stored in fields or arrays remain open. Queue, hash set, and dictionary are not contiguous spans; their `Ptr` property only exposes their backing first-slot view and does not represent a packed logical sequence.

Scope-bound and readonly alias locals now transfer owned call results or retain borrowed references until lexical cleanup. Replacement assignments acquire the new reference before releasing the old one, and captured aliases are owned and released by their closure environment while captured readonly parameters remain borrowed. Finalizer-backed execution tests cover call, property, indexer, assignment, class-reference swaps, and lambda-capture paths. Scoped array element stores now check same-block declaration order for named scope-bound values in both ordinary and multiple assignment, while preserving direct scoped-element initialization and inner-scope containers. Scope-bound delegate closures carry the latest captured scoped allocation order so scoped arrays and class fields can retain them safely; heap storage and returns remain rejected. Multiple assignment now binds and calls computed property/indexer setters after all RHS values and target sub-expressions are evaluated; pointer dereferences and struct accessors are also covered. Generic lower-bound inference preserves nullable reference, scalar, and struct types, including a `null` argument when another argument supplies the inferred type. Exact bounds now apply inside invariant managed arrays, same-definition constructed generic types, and constructed generic base/interface matches, so incompatible closed arguments produce LS1101 instead of a fabricated common type. Inference tests also assert that return targets and constraints do not supply type arguments.

Exception handler globals are verified and emitted as thread-local storage for the host and x86_64 Linux targets, including with LLVM optimization. Executing concurrent native programs still requires a compatible linker/runtime test environment; the MCJIT test harness does not exercise its cross-thread waiting path. Nullable-flow analysis now rechecks while, do, for, and for-in bodies until the iteration state converges; constant `if` branches and conditional expressions select only reachable null-state outcomes, and constant `if` branches also drive return-path analysis. Constant-false `while`/`for` bodies no longer affect post-loop flow. Loop break/continue transfer states from dead constant branches are discarded while the dead branches are still checked. The analyzer emits `LS3001` for dead branches/bodies and still analyzes them for errors. Out-parameter definite assignment now accounts for constant branches, loop break/continue exits, switch-local breaks, exception types from explicit throws, ordered typed-catch routing, catch bodies, and finally effects on normal completion, returns, and loop/switch transfers. Exceptions from calls and other potentially throwing operations remain unknown and are conservatively routed through compatible catches. More precise early-exit reachability remains open. Generic `IEnumerable<T>` iteration now uses the specified iterator protocol for class and boxed-struct sources, with malformed contracts diagnosed and iterator references released on loop exits. Continue broadening readonly and closure-container escape checks, and unify strings, arrays, and classes under a shared, versioned runtime ABI. Remaining v1 language work includes complete generic method inference and complex nested receiver/argument validation, broader nested-closure cases, broader switch exhaustiveness analysis beyond finite and integral domains, cross-target aggregate execution, and complete scope/readonly escape analysis. Switch declaration variables now remain available across compatible combined and comma-separated alternatives. The former LMC3101/LMC3102 trap warnings were removed for operations that now route failures through generated exception handlers.

Scope receiver escape analysis now follows unqualified implicit-`this` calls through method bodies and covers switch, throw, try, catch, and finally paths. It distinguishes value reads and writes on `this` from values that may alias the receiver. Virtual calls resolve against the receiver's known runtime class and conservatively reject open class hierarchies; interface calls inspect known dispatch-table implementations and reject open implementation sets. Regression coverage checks escaping overrides, safe closed overrides and interface implementations, explicit primitive-field reads, reference-field writes, nested safe method calls, open virtual receivers, and base-qualified calls. Required `LS3101` constant type-test warnings now recognize exact, base-class, implemented-interface, inherited-interface, delegate-root, and object-root relationships while leaving open object/interface and virtual-class tests undecided; interface-to-object switch patterns also have execution and return-flow coverage. `is T name` bindings are now scoped to the true arm of conditional expressions, including captured closures; capture discovery now accounts for patterns nested in return expressions and initializers. Conditional expressions now record their semantically selected result type for lowering, promote numeric arms before the LLVM join, reject arms without a valid common implicit-conversion target, lift `null` against nullable scalar/aggregate and reference types, and preserve nullable class/array results when `null` is the first arm. Tests execute both null-arm orders and cover nullable scalar, struct, and enum values, arrays, delegates, and classes. Broader alias and closure-container escape analysis remains incomplete.

Parenthesized switch patterns now preserve the contained pattern tree, so grouping combined `and`/`or` patterns does not change binding or execution. Tuple types, expressions, patterns, and deconstruction are explicitly outside language version 0.3; recognized tuple-shaped declarations, expressions, and switch patterns receive one focused `LS0001` diagnostic with local recovery.

Null-conditional reads from nullable arrays now return correctly nullable scalar, value, and reference results. Reference-element reads retain the result independently of the array slot, including nullable element types without adding a second nullable marker; finalizer-backed tests verify that releasing either owner does not destroy the object prematurely.

Null-conditional method calls now lift delegate results to nullable delegate references, alongside the existing scalar, aggregate, string, array, class, and interface results. The receiver still gates argument evaluation, and execution coverage checks both the null short-circuit path and the owned delegate returned by a non-null receiver.

Null-conditional string indexing now returns `char?`, skips index evaluation for a null receiver, preserves the UTF-16 code-unit bounds exception, and releases an owned temporary string on success, null, or exceptional exit. Runtime tests cover all three paths.

Identifier scanning now follows the v0.3 Unicode grammar exactly: Unicode letters or underscore may begin an identifier, and subsequent characters may also be decimal digits. Combining marks, format characters, connector punctuation, and Unicode letter-number categories are rejected with a source diagnostic, while supplementary-plane letters remain supported. Invalid starting runes are rejected by the lexer before identifier scanning, preventing malformed Unicode input from stalling tokenization.

Target triple architecture classification is shared between semantic ABI sizing and LLVM target initialization. ARM/Thumb variants (including `armv7a`) use 32-bit pointers and initialize the ARM backend; AArch64 ABI aliases (including `arm64e` and `aarch64_32`) use the AArch64 backend with their ABI-specific pointer width. Cross-target struct layout is checked through LLVM object emission for these triples.

The compiler cancellation token now reaches lexing, parsing, generic expansion and its AST walks, semantic expression/statement analysis, LLVM method/expression/statement emission, and LLVM optimization/verification/object-emission boundaries. The build API propagates cancellation through the native backend and still cleans temporary artifacts before returning. Long lexical scans check cancellation periodically, with regressions for in-progress front-end cancellation and cancelled object emission.

Native build requests now validate the requested LLVM target machine before parsing or lowering source and return an `LMC2001` diagnostic without creating output directories for unsupported triples. Host-only `link.exe` and `clang-cl` fallbacks reject cross-target links instead of risking an artifact for the wrong platform; target-capable `clang` remains available for cross-target linking.

Executable entry-point binding now accepts each specified form: `void`/`int32` `Main()` and `void`/`int32` `Main(string[] args)`. POSIX startup uses `argc`/`argv`, omits `argv[0]`, and decodes UTF-8 with replacement for malformed sequences. Windows startup reads the wide command line with `GetCommandLineW` and `CommandLineToArgvW`, converts each UTF-16 argument to normalized UTF-8, and links `shell32` for the parser API. Both paths build an owned managed string array and release it after `Main` returns or if entry-type initialization fails. JIT conformance tests exercise empty arguments, ASCII, multi-byte Unicode, supplementary UTF-16 pairs, malformed UTF-8, void/int32 signatures, invalid parameter types, duplicate entry points, balanced ownership, and Windows-target LLVM object emission.

Native static-library builds now discover LLVM and Visual Studio librarian tools from common installation roots when they are not on `PATH`. Windows builds use librarian-compatible arguments. Compiler runtime trap stubs and compiler-provided intrinsic constructors use module-local linkage, preventing duplicate symbols when independently built archives are linked together; a Windows integration test links two archives and runs a native caller. This addresses duplicate definitions for the tested path, while shared exception/thread-local runtime state and a distributable runtime package remain open ABI work.

`System.Weak<T> where T : class` now provides `IsAlive` and nullable `Target`. A target's weak-control block is created lazily in a common class/string/array object-header slot; multiple weak wrappers share a handle count. Target promotion locks against final strong release, increments the strong count before returning an owned target, and returns null once destruction starts. Strings and arrays use the same header slot, and immortal literals/static instances use detached controls. A native smoke fixture covers multiple weak handles, target promotion/destruction, dynamic and literal strings, and arrays. The runtime ABI version is now 2 because the managed object header changed; the language spec describes the new layout and weak-target race semantics.

The build API suite now includes a native end-to-end test that compiles two `.ls` files into a host executable, launches it, and checks its process exit code. This supplements LLVM-JIT semantic tests with direct object emission, native linking, artifact publication, and operating-system execution coverage.

The IO runtime now has a synchronous `System.IO.Stream` base and `MemoryStream`. Only the `uint8[]` `Read` and `Write` operations are pure virtual; the base provides `ReadUInt8`, `WriteUInt8`, `CopyTo`, `Close`, and default unsupported seeking/length operations. `MemoryStream` implements reading, writing, seeking, truncation/extension, `ToArray`, fixed-buffer constructors, and an unsafe pointer to its underlying array. Async, timeout, and `Dispose` APIs are intentionally not included.

The compiler now supports safe ref locals (`var value = ref location`, `let value = ref location`, or `ref T value = ref location`), `return ref`, and stack-bound `ref struct` declarations. Ref locals alias existing storage and retain managed array/class owners for the lexical scope; ref returns currently allow non-scoped `ref`/`out` parameters and mutable static fields, while returning local or instance-owned storage is rejected. Ref fields and ref-local lambda captures remain unsupported. `Span<T>` and `ReadOnlySpan<T>` are ref structs and hold their array, string, or collection backing-array owner through slicing and read-only conversion; raw pointer constructors remain the unsafe caller's responsibility. The native smoke fixture compiles and exits successfully for inferred/explicit ref locals, array and class-field aliases, ref-return chaining, and a ref struct. Focused xUnit tests also cover those cases and invalid escapes; the test host currently stalls during discovery before reporting any tests, so those xUnit cases still need a run in a functioning test host.

Primitive byte conversion helpers now use a canonical little-endian representation for Bool, Char, all fixed-width signed and unsigned integers, Float, and Double. Each primitive exposes instance `GetBytes()` and `GetBytes(scope uint8[])`; `FromBytes(scope uint8[])` is static. Native `int`/`uint` use an 8-byte wire representation so serialized values have a stable width across 32-bit and 64-bit targets. Float and Double preserve IEEE-754 bits. The compiler now resolves instance methods and `this` through primitive keyword aliases, allowing the runtime API to be called on values such as `number.GetBytes()`. The CLI and a standalone native smoke fixture build successfully; the fixture verifies byte order, negative signed values, all major primitive categories, round-trips, destination writes, and short-buffer exceptions. Big-endian cross-target verification could not be run because the bundled LLVM backend does not enable the `powerpc64` target.

Signed integer byte deserialization now uses the primitive `MaxValue` constants and the corresponding unsigned `MaxValue` for two's-complement reconstruction instead of duplicated decimal limits.

`String` now converts implicitly to `ReadOnlySpan<char>`. `System.Text.Encoding` provides UTF-8 and little-endian UTF-16 (`Unicode`) implementations with byte encoding, decoding, and decoded character counts; `String.GetBytes` and `String.FromBytes` use UTF-8 by default and accept an explicit encoding. The generic specializer now rewrites closed generic type references in concrete declarations to their monomorphized names, enabling `ReadOnlySpan<char>` in method signatures and member access. The runtime static-library build succeeds. Focused encoding execution tests and non-Windows target checks remain to be added.
